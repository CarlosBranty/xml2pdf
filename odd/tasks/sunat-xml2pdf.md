# sunat-xml2pdf

Objective: open-source tool that converts SUNAT electronic documents (UBL 2.1 XML) into printable, configurable PDFs, shipped as CLI, web (WASM) and desktop (auto-print).
Branch: `feat/sunat-xml2pdf`. Delivery strategy: `single-pr` (user: "haremos todo de una pasada"). Forecast: well above 400 authored lines; accepted by the user's single-pass instruction.
Test runner: `cargo test --workspace` (tests are written last by explicit user instruction, see S7).

## Specs

- **S1** "herramienta, opensource para poder convertir xml de sunat a pdf para que sea imprimible". Parse SUNAT UBL 2.1 XML and produce a PDF "representación impresa" including QR code and signature hash. Assumption (from the accepted recommendation): document types are factura (01), boleta (03), nota de crédito (07) and nota de débito (08). ZIP files containing the XML are accepted as input (assumption: SUNAT downloads are often zipped).
- **S2** "con rust talvez, par aque sea multiplataforma". Rust workspace; the same core runs on Linux, macOS, Windows and WASM.
- **S3** "una version web par que se pueda generar de la misma manera". Static web app; the PDF is generated in the browser by the same core compiled to WASM. No backend, the XML never leaves the browser. Changed by L17: "el interfaz debe ser mas sencillo copio y pego un xml, o arrastro un xml a un drag and drop o slecciono el archivo xml, entonce pongo convertir y me genera el pdf con sus previsualizaciones en todos los formatos y tambien puedo elegir donde  guardarlo o puedo elegir si quiero imprimir" and "el interfaz con el estilo visual de qlab.pe". Flow: paste the XML text, drop a file, or pick a file; press "Convertir"; a preview appears for each of the four formats; each one can be saved (choosing the location when the browser allows it) or printed. Visual style after the attached qlab.pe capture: warm gray page, large rounded cards with a thin black outline, pink hero, wide uppercase display type, orange call to action, dark and blue cards, pill tags. Assumptions: this applies to the web app (the desktop window keeps its settings-and-log layout); logo, issuer texts, footer, QR and custom template move into a collapsed section so the main flow stays simple.
- **S4** "otra verison tambien de escritorio para autoimprimir todo". Desktop app (Tauri 2) that watches a folder and automatically converts and prints every new XML.
- **S5** "tengan opcion de tener pdf imprimibles y configurables editables en diferentes formatos". Formats: A4, A5, ticket 80 mm, ticket 58 mm. Configurable: logo, extra issuer texts, footer. Editable: templates are plain Typst files and a custom template can replace the built-in one. Changed by L14: "Quiero que tenga este formato el de a4. y no le pongas colores que los comporbantes sean como los de nubefact". The A4 page follows the attached Nubefact invoice layout: logo and issuer on the left; a gray rounded box with RUC, document title and number on the right; a "DATOS DEL CLIENTE" box next to a box with "FECHA EMISIÓN", "FECHA DE VENC." and "MONEDA"; an items table with the columns "CANT.", "UM", "CÓD.", "DESCRIPCIÓN", "V/U", "P/U", "IMPORTE" and striped filler rows; totals "GRAVADA", "IGV 18.00 %", "TOTAL" with the currency symbol in its own column; an "IMPORTE EN LETRAS" box; a legal text box with "Resumen:" next to the QR box. No colors: black and gray only, and the accent color option is removed (assumption: an option without effect would mislead). Assumption: A5 shares the page template, and the Nubefact total labels are also used on tickets.
- **S6** "esto debe poder depslegarse con gi gd a un dokploy". Assumption: "gi gd" means CI/CD. Dockerfile serving the static web build, plus a CI workflow and a Dokploy deploy trigger.
- **S7** "primero planifica las pruebas para el final por que haremos todo de una pasada". Plan first; implement everything in one pass; tests are written at the end (overrides the default test-first policy).
